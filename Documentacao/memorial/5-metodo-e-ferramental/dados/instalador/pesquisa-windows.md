# Pesquisa: ambientes limpos de Windows para provar o instalador

Data de acesso de todas as fontes: 18/11/2026. Pesquisa só de leitura. Páginas do Microsoft Learn e dos projetos oficiais; onde só achei fonte secundária, está dito.

## 1. Windows Sandbox

**Requisitos.** Arquitetura AMD64 ou Arm64 (Arm64 no Windows 11 22H2 em diante), virtualização ligada na BIOS, no mínimo 4 GB de RAM (8 GB recomendado), 1 GB de disco livre (SSD recomendado), no mínimo 2 núcleos (4 com hyper-threading recomendado). Edições: Pro, Enterprise, Education e Pro Education/SE; Home não suporta.
Fontes: https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-install e https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-overview (acesso 18/11/2026).

**Como ativar.** Interface: "Ativar ou desativar recursos do Windows", marcar Windows Sandbox, reiniciar se pedir. PowerShell: abrir como Administrador e rodar `Enable-WindowsOptionalFeature -FeatureName "Containers-DisposableClientVM" -All -Online`. Portanto pede administrador e, normalmente, reinício. Uma vez ativado, o uso do dia a dia (abrir o Sandbox, abrir um `.wsb`) não foi documentado como exigindo administrador.
Fonte: página de instalação acima.

**Convivência com WSL2 e Hyper-V.** Não achei página do Learn que diga literalmente "Sandbox convive com WSL2". O que está documentado: o Sandbox usa o hipervisor da Microsoft ("relies on the Microsoft hypervisor to run a separate kernel"), a FAQ o compara com VMs Hyper-V como coisa distinta, e o WSL2 usa "um subconjunto da arquitetura Hyper-V" (Virtual Machine Platform). Ou seja, todos usam o mesmo hipervisor do Windows; a convivência é consequência da arquitetura, não uma frase documentada. Item para teste prático na máquina (ver seção final). Limite documentado: só uma instância do Sandbox por vez.
Fontes: https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-overview ; https://learn.microsoft.com/en-us/windows/wsl/faq (acesso 18/11/2026).

**O que o `.wsb` permite** (XML, extensão `.wsb`, vale para Windows 10 build 18342 ou Windows 11):
- `MappedFolders`/`MappedFolder` com `HostFolder`, `SandboxFolder` e `ReadOnly` (true/false, padrão false). A pasta do host precisa existir, senão o Sandbox não inicia. Caminhos relativos não são suportados; a partir do Windows 11 23H2 aceita variáveis de ambiente no caminho. As pastas são mapeadas antes do comando de logon. Usuário padrão: `WDAGUtilityAccount`.
- `MemoryInMB`: se o valor não bastar para iniciar, sobe automaticamente para o mínimo de 2048 MB. O padrão do Sandbox aberto pelo menu é máximo de 4 GB.
- `Networking`: Enable, Disable ou Default (Default liga a rede por um switch virtual, o "Default Switch" do Hyper-V).
- `LogonCommand`/`Command`: um único comando executado após o logon (conta do contêiner, que deve ser administradora). Cenários de vários passos devem ir para um script em pasta mapeada.
- Outros: `vGPU`, `AudioInput`, `VideoInput`, `ProtectedClient`, `PrinterRedirection`, `ClipboardRedirection`.
- Exemplo oficial com pasta somente leitura e script de logon: `<MappedFolder><HostFolder>C:\sandbox</HostFolder><SandboxFolder>C:\sandbox</SandboxFolder><ReadOnly>True</ReadOnly></MappedFolder>` com `<LogonCommand><Command>powershell.exe -ExecutionPolicy Bypass -File C:\sandbox\SwapMouse.ps1</Command></LogonCommand>`.
Fontes: https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file ; https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-sample-configuration (acesso 18/11/2026).

**Persistência.** Fechar o Sandbox apaga tudo. Desde o Windows 11 22H2, reinícios iniciados de dentro do Sandbox preservam os dados (útil para instalador que pede reboot). Pasta mapeada com escrita persiste depois que o Sandbox é descartado.
Fonte: página overview acima.

**Defender dentro do Sandbox.** NÃO CONFIRMEI em fonte primária. Nem a página overview, nem a FAQ, nem a de arquitetura dizem se o Microsoft Defender roda dentro do Sandbox, nem se a proteção em tempo real pode ser ligada e desligada lá. A busca por issues no repositório oficial (https://github.com/microsoft/Windows-Sandbox/issues?q=defender) não achou nada que responda. Só há opinião de fórum (não oficial) de que não há interface do Defender dentro do Sandbox. Precisa de teste prático. Pelo que o Sandbox é (a mesma imagem do host, com `Set-MpPreference` sendo apenas um cmdlet do sistema), o comando da seção 7 é o caminho a testar, mas isso é inferência minha.

**Loja e winget dentro do Sandbox.** A FAQ diz que apps inbox (por exemplo Store e Bloco de Notas) e recursos opcionais do Windows não são suportados; a Store não existe no Sandbox, mas pacotes `.appx` podem ser instalados. A página do WinGet diz: "Windows Sandbox does not include WinGet, nor the Microsoft Store app". Procedimento oficial (PowerShell do Windows, no Sandbox):
```
$progressPreference = 'silentlyContinue'
Install-PackageProvider -Name NuGet -Force | Out-Null
Install-Module -Name Microsoft.WinGet.Client -Force -Repository PSGallery | Out-Null
Repair-WinGetPackageManager -AllUsers
```
A página diz que a alternativa é baixar o pacote mais recente do WinGet na página de releases do GitHub. Observação minha: o `-AllUsers` no exemplo oficial roda dentro do Sandbox, onde a conta é administradora.
Fontes: https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-faq ; https://learn.microsoft.com/en-us/windows/package-manager/winget/ (acesso 18/11/2026).

**Windows 11 24H2 e 25H2.**
- A partir do 24H2 há uma versão nova do Sandbox distribuída pela Microsoft Store: interface WinUI 3, controles em tempo de execução (área de transferência, áudio/vídeo, compartilhamento de pasta pelo menu "..."), e linha de comando em prévia.
- Pré-requisitos do upgrade: Sandbox já instalado como recurso, Windows 11 24H2 com "KB10D ou later" (texto literal da página; o valor parece um código interno, tratar como pendente de conferência), internet para Store e Windows Update. Ao abrir o Sandbox pelo Iniciar, ele tenta se atualizar sozinho (30 segundos a 2 minutos); se falhar, a instalação continua em segundo plano e fica na fila "Updates & downloads" da Store.
- Como saber a versão: `Get-AppxPackage -Name WindowsSandbox | Select-Object Version` (vazio significa versão antiga) ou `wsb --version`.
- CLI `wsb` (24H2 em diante): `wsb start [--config "<Configuration>...</Configuration>"]`, `wsb list`, `wsb exec --id <id> -c <comando> -r <System|ExistingLogin> [-d <dir>]`, `wsb stop --id`, `wsb share --id -f <host> -s <sandbox> [-w]`, `wsb connect --id`, `wsb ip --id`, parâmetro `--raw` para JSON. Limitações: `exec` não devolve saída do processo; para `ExistingLogin` precisa de sessão ativa (fazer `connect` antes). Pasta compartilhada por `share` é somente leitura salvo `--allow-write`.
- Nota do 24H2: apps inbox como Calculadora, Fotos, Bloco de Notas e Terminal não estão disponíveis dentro do Sandbox.
- Relato de problemas (não oficial, issues): Sandbox travando o host no 24H2 depois das atualizações de fevereiro de 2025 (issue #84, aberta) e crash com Edge na build 26300.9539 (issue #131, fechada em 20/10/2026), em https://github.com/microsoft/Windows-Sandbox/issues?q=defender.
Fontes: https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-versions ; .../windows-sandbox-cli ; .../windows-sandbox-faq ; .../windows-sandbox-install (acesso 18/11/2026).

**Mesma versão do Windows do host?** Sim. A FAQ: "Windows Sandbox only allows you to use the same build as your host OS." A arquitetura confirma: a imagem é gerada dinamicamente a partir do Windows instalado no host ("Dynamic Base Image"), cerca de 500 MB em disco. Consequência para o plano: o Sandbox NÃO serve para provar Windows 10; só prova a build do host (Windows 11 10.0.26200).
Fontes: https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-faq ; .../windows-sandbox-architecture (acesso 18/11/2026).

## 3. Hipervisores no Windows 11 Pro

**Hyper-V.** Ativar: PowerShell como Administrador, `Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All` (responder Y para reiniciar), ou DISM `DISM /Online /Enable-Feature /All /FeatureName:Microsoft-Hyper-V`, ou "Ativar ou desativar recursos do Windows". Requisitos do host: Windows 10/11 Pro ou Enterprise (nunca Home), CPU de 64 bits com SLAT e extensão de monitor de VM, mínimo de 4 GB de RAM. Pede administrador e reinício. Fonte: https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/get-started/install-hyper-v (acesso 18/11/2026).

**Pontos de verificação (checkpoints).** Dois tipos no Windows 10/11: Standard (guarda também a memória) e Production (usa VSS, sem memória; é o padrão). `Set-VM -Name <vm> -CheckpointType Standard|Production|ProductionOnly`; criar `Checkpoint-VM -Name <vm>`; voltar `Restore-VMCheckpoint -Name <checkpoint> -VMName <vm> -Confirm:$false`. Aplicar um Production deixa a VM desligada; aplicar um Standard devolve o estado exato, inclusive programas abertos. Os checkpoints ficam em arquivos `.avhdx` (não apagar à mão). Fonte: https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/checkpoints (acesso 18/11/2026).

**Máquina virtual dentro de máquina virtual.** Se um dia for necessário rodar o Sandbox dentro de uma VM Hyper-V, o Learn manda, no host: `Set-VMProcessor -VMName <VMName> -ExposeVirtualizationExtensions $true`. Também documenta WSL2 em VM aninhada como suportado. Fontes: página de instalação do Sandbox e https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/nested-virtualization (acesso 18/11/2026).

**VirtualBox e VMware com o hipervisor do Windows ativo.**
- A FAQ do WSL diz que alguns apps de terceiros não funcionam com o Hyper-V em uso, mas que VirtualBox 6 e posteriores e VMware passaram a suportar a coexistência pela API Windows Hypervisor Platform (WHP). https://learn.microsoft.com/en-us/windows/wsl/faq (acesso 18/11/2026).
- Página de instalação do Hyper-V: apps como VMware Workstation e VirtualBox podem não iniciar VMs ou ficar instáveis quando o hipervisor do Hyper-V está ativo. Mesmo link da seção Hyper-V.
- VirtualBox: versão atual 7.2.22; pacotes da plataforma sob GPLv3; Extension Pack sob PUEL (uso pessoal e educacional). https://www.virtualbox.org/wiki/Downloads (acesso 18/11/2026). O manual do VirtualBox (https://www.virtualbox.org/manual/ch10.html) diz "Do not run other hypervisors" junto ao VirtualBox; a seção específica sobre Hyper-V/NEM não foi encontrada nessa página (não confirmado em fonte primária).
- VMware Workstation Pro: a base de conhecimento da Broadcom diz que "as of May 6th 2024 Workstation Pro is now free" para uso pessoal, com conta gratuita no portal de suporte da Broadcom, e que uso comercial exige licença paga; a mesma página também tem uma frase que diz que exige licença paga "para uso pessoal e comercial", contradição interna (provavelmente texto antigo). Windows 11 consta como host suportado. A página não trata de WHP. https://knowledge.broadcom.com/external/article/315616/vmware-workstation-17x-pro-sales-licensi.html (acesso 18/11/2026). Mudanças posteriores de licença: não confirmadas (relatos secundários dizem que passou a ser gratuito também para uso comercial; não verifiquei em fonte primária).

**Qual pede menos mudança numa máquina que já tem WSL2 e hipervisor ativo?** Conclusão (inferência a partir das fontes): o Hyper-V, porque o hipervisor já está ativo e é o mesmo que o WSL2 usa; só se acrescenta o recurso Microsoft-Hyper-V (administrador e um reinício) e o Hyper-V Manager, sem trocar de hipervisor. Traz de graça Geração 2, vTPM, Secure Boot e checkpoints. VirtualBox ou VMware passariam a rodar sobre a WHP, com desempenho menor e risco de instabilidade (o próprio Learn avisa), e exigem instalar driver de rede/kernel. Nenhuma fonte primária mede o desempenho.

## 4. winget em instalação nova

**Disponibilidade.** A página do WinGet no Learn: o WinGet está disponível no Windows 11, em versões modernas do Windows 10 e no Windows Server 2025 como parte do App Installer ("Instalador de Aplicativo"), componente de sistema entregue e atualizado pela Microsoft Store. Nota oficial: "WinGet will not be available until you have logged into Windows as a user for the first time, triggering Microsoft Store to register the Windows Package Manager as part of an asynchronous process." Requer Windows 10 1809 (build 17763) ou superior. Fonte: https://learn.microsoft.com/en-us/windows/package-manager/winget/ (acesso 18/11/2026; página atualizada 21/07/2026). A página não afirma que a versão do `winget` embarcada na mídia seja nova o bastante para este instalador; versão mínima útil: o troubleshooting do winget-cli cita 1.6.3482 como limite abaixo do qual há falhas (`winget --info`), seguido de `winget source update`.

**Formas oficiais de garantir.**
1. `Add-AppxPackage -RegisterByFamilyName -MainPackage Microsoft.DesktopAppInstaller_8wekyb3d8bbwe` (registra o App Installer que já está no sistema, para o usuário atual; dica oficial para o caso "acabei de logar e ainda não existe"). Fonte: página do WinGet acima.
2. Módulo Microsoft.WinGet.Client da PowerShell Gallery (versão atual 1.29.380, publicada 21/09/2026, mínimo PowerShell 5.1, Desktop e Core): `Install-Module Microsoft.WinGet.Client` e `Repair-WinGetPackageManager` (com `-AllUsers` no procedimento do Sandbox). https://www.powershellgallery.com/packages/Microsoft.WinGet.Client (acesso 18/11/2026). Ainda mais: a última versão do próprio winget-cli é a 1.29.380 (https://github.com/microsoft/winget-cli/releases/latest, acesso 18/11/2026).
3. Instalar o pacote MSIX: três origens listadas no troubleshooting oficial: Microsoft Store, página de releases do GitHub e `aka.ms/getwinget`. Para provisionar para a máquina inteira: `Add-AppxProvisionedPackage -Online` com os caminhos de pacote, licença e dependência (`-DependencyPackagePath`; Microsoft.VCLibs é dependência citada). Fonte: https://github.com/microsoft/winget-cli/tree/master/doc/troubleshooting (acesso 18/11/2026). Dependência Microsoft.UI.Xaml: não citada nessa página (não confirmado aqui).
4. Se o comando existe mas está quebrado: `Reset-AppxPackage` (Windows 11) ou `Add-AppxPackage -DisableDevelopmentMode -Register` com o AppxManifest instalado (Windows 10); verificar alias de execução do app e PATH (`%LOCALAPPDATA%\Microsoft\WindowsApps`). Mesma fonte.

**Sem administrador?** Registrar/instalar um MSIX para o usuário atual (`Add-AppxPackage`) não pede administrador pelo que a documentação indica, mas nenhuma página afirma isso de forma explícita (a página do winget-cli não declara requisito de administrador; só o provisionamento para todos os usuários, `Add-AppxProvisionedPackage -Online`, é operação de máquina e em geral exige elevação, o que é inferência minha). O `winget` em si, sem administrador, funciona, mas instaladores cujo escopo é `machine` pedem elevação via UAC e falham se o usuário recusar (https://learn.microsoft.com/en-us/windows/package-manager/winget/, seção "Administrator considerations").

Para evitar administrador, usar `winget install --scope user`.

Pede administrador; sem administrador, o plano de baixar o zip é necessário. Observação: o manifesto mais novo no winget é 12.x/13.x, não 11.8.

## 5. Dependências de sistema em Windows limpo

**PHP 8.2 e o Visual C++ Redistributable.**
- O manifesto `PHP.PHP.8.2` 8.2.35 declara dependência de pacote: `Microsoft.VCRedist.2015+.x64` para x64 (e `.x86` para x86). Confirmado. (Fonte: manifesto acima, acesso 18/11/2026.)
- O build é `vs16` (Visual Studio 2019). A página de download do PHP para Windows (https://www.php.net/downloads.php?os=windows, que é o destino do redirecionamento de windows.php.net/download) diz que os builds "require the Visual C++ Redistributable for Visual Studio 2015-2022 x64 or x86 installed", com os links https://aka.ms/vs/17/release/vc_redist.x64.exe e `.../vc_redist.x86.exe`. A página só exibe a série 8.5 no momento; o texto sobre o redist é geral ao site. A série 8.2 está nos arquivos: https://downloads.php.net/~windows/releases/archives/ (acesso 18/11/2026, listagem não aberta).
- Consequência: o winget instala o VC++ Redist como dependência automaticamente. Esse redist é instalado em escopo de máquina; se o winget rodar sem administrador, a instalação do redist pode pedir UAC (inferência; o manifesto do redist não foi lido).
- Se o Windows limpo já traz `vcruntime140.dll`? NÃO confirmei em fonte oficial. A página do Learn diz que o redistributable "must be installed on the target system along with the app" e não afirma que o Windows o traga. Tratar como ausente em Windows limpo. Fonte: https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist (acesso 18/11/2026). Links permanentes oficiais: https://aka.ms/vc14/vc_redist.x64.exe (o pacote x64 contém binários ARM64 e x64), https://aka.ms/vc14/vc_redist.x86.exe. Versão VS 2026 do redist: só Windows 10 e 11, Server 2016, 2019, 2022 e 2025. O instalador aceita opções de linha de comando (por exemplo `/install /quiet /norestart`, descritas em https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files#command-line-options-for-the-redistributable-packages; página não aberta, não confirmado).

**MariaDB 11.8, zip winx64.** NÃO CONFIRMADO. As páginas do MariaDB sobre o zip (https://mariadb.com/docs/server/server-management/install-and-upgrade-mariadb/installing-mariadb/binary-packages/installing-mariadb-windows-zip-packages e https://mariadb.com/kb/en/installing-mariadb-windows-zip-packages/) não mencionam o VC++ Redistributable, nem administrador, nem versão mínima do Windows. **Ollama para Windows.** Página oficial https://docs.ollama.com/windows (acesso 18/11/2026): requer Windows 10 22H2 ou mais novo (Home ou Pro); driver NVIDIA 551.61 ou mais novo para GPU NVIDIA; não exige administrador, instala no diretório do usuário por padrão (`OllamaSetup.exe /DIR="d:\pasta"` para mudar); pelo menos 4 GB para os binários mais o espaço dos modelos; modelos em `OLLAMA_MODELS`; serviço em `http://localhost:11434`; para rodar como serviço, usar o `ollama-windows-amd64.zip`. A página não documenta a opção `/SILENT`; o manifesto winget usa instalador Inno, que em geral aceita `/SILENT` (inferência minha, a conferir). Não consta dependência de VC++ ou .NET.

**Chromium do Playwright.** A página de introdução do Playwright (https://playwright.dev/docs/intro e a de Python https://playwright.dev/python/docs/intro, acesso 18/11/2026) lista como sistemas suportados "Windows 11 and later, Windows Server 2019 and later, or WSL" (o Windows 10 não está listado) e, para Python, 3.8 ou superior. Não documenta pré-requisitos de DLL do Chromium no Windows, nem se `playwright install` exige administrador. O Windows 10 aparentemente deixou de ser suportado oficialmente; isso precisa de teste prático.

**PyInstaller `--onefile`.** Página de requisitos (https://pyinstaller.org/en/stable/requirements.html): "PyInstaller runs in Windows 8 and newer". Última versão: 6.22.3 (12/09/2026); suporte ao Python 3.14 desde a 6.15.0 (03/08/2025) (https://pyinstaller.org/en/stable/CHANGES.html). Modo onefile: cria pasta temporária `_MEIxxxxxx` no diretório temporário, extrai os arquivos e apaga ao terminar (https://pyinstaller.org/en/stable/operating-mode.html). Aviso oficial: "Do not give administrator privileges to a one-file executable on Windows." As notas de versão citam proteção contra antivírus travando DLLs na limpeza do diretório temporário (6.11.1) e carga prévia de `VCRUNTIME140.dll` do sistema no bootloader com splash (6.10.0). A documentação não diz se o Windows 10 limpo precisa do UCRT por separado; o Python 3.14 documentado suporta Windows 10 e mais novo. Os `.pyd` do Python são compilados com MSVC, e o Python empacota `vcruntime140.dll` em seus binários normalmente; a necessidade de redist para o executável gerado NÃO foi confirmada em fonte primária.

**.NET.** Nenhum dos pacotes acima (PHP, MariaDB, Ollama, Python, Chromium do Playwright, PyInstaller) aparece nas fontes lidas com dependência de .NET. Nenhuma fonte nega explicitamente, mas nada indica necessidade.

## 6. Python sem winget

Referência: https://docs.python.org/3.14/using/windows.html (acesso 18/11/2026) e https://www.python.org/downloads/windows/ (acesso 18/11/2026).
- **Versão atual:** Python 3.14.10 (25/10/2026), instalador de 64 bits em https://www.python.org/ftp/python/3.14.10/python-3.14.10-amd64.exe. Python install manager versão 26.4 (09/10/2026), MSIX e MSI.
- **Suporte do Windows:** o Python 3.14 suporta Windows 10 e mais novo.
- **Instalador tradicional `.exe`:** funciona, mas está descontinuado desde o 3.14 e não será produzido a partir do 3.16. "Install Now" não exige administrador, salvo se for preciso atualizar o C Runtime ou instalar o gerenciador para todos os usuários. Parâmetros silenciosos documentados: `/quiet` (sem interface), `/passive` (só progresso), `/simple`, `/log <arquivo>`, `/layout`; opções `InstallAllUsers` (padrão 0), `PrependPath` (padrão 0), `Include_launcher` (padrão 1), `InstallLauncherAllUsers`, `Include_test` (padrão 1). Exemplo adaptado: `python-3.14.10-amd64.exe /quiet InstallAllUsers=0 PrependPath=1 Include_test=0 Include_launcher=0`. Observação: a página dá exemplos com `InstallAllUsers=1`; o por-usuário é a combinação das opções documentadas.
- **Python install manager (`py install`):** instala runtimes só por usuário ("does not support installing runtimes per-machine"). Duas rotas: Microsoft Store, ou `Add-AppxPackage <caminho do MSIX>`. Roteiro programático da documentação: `winget install 9NQ7512CXL7T -e --accept-package-agreements --disable-interactivity` e depois `py install --configure -y`. Para instalar o 3.14: `py install 3.14`. Para extrair sem registrar: `py install --target=<pasta> <TAG>`. Para Windows Server 2019 a documentação manda usar o MSI (instalação por máquina, administrador).
- **Pacote NuGet:** `nuget.exe install python -ExcludeVersion -OutputDirectory .` (opção `-Version 3.x.y`); o interpretador fica em `.\python\tools\python.exe`. Não registra no sistema e não atualiza; pacotes `python` (x64), `pythonx86`, `pythonarm64` e versões `-freethreaded`. Não exige administrador (é só extração).
- **Pacote embutível:** "A minimal Python environment" para embutir em outros aplicativos. Vem SEM Tcl/Tk, SEM pip e sem documentação; "Using pip ... is not supported with this distribution". Por que não serve para `venv`: a página não menciona `venv` (não confirmado em fonte); a razão prática é que a distribuição é pensada para embutir, sem o módulo `venv`/`ensurepip` da instalação normal e sem pip suportado. Instalar: `py install 3.14-embed --target=<pasta>`.
- **uv da Astral:** instalador independente. Windows: `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`. macOS e Linux: `curl -LsSf https://astral.sh/uv/install.sh | sh` (ou `wget -qO- https://astral.sh/uv/install.sh | sh`). Instala em `~/.local/bin` (`$HOME\.local\bin` no Windows) e pode editar o perfil do shell; `UV_NO_MODIFY_PATH=1` desliga. A página não diz se há exigência de administrador; o destino é a pasta do usuário. `uv python install 3.14` baixa builds do projeto python-build-standalone da Astral (a documentação diz que "Python does not publish official distributable binaries"; ou seja, não é o instalador do python.org). Se não houver Python, `uv venv` instala um antes de criar o ambiente. Licença: dupla Apache-2.0 e MIT, à escolha. Plataformas: macOS, Linux e Windows. Funciona igual nos três pelos comandos documentados; a página de instalação do Python não trata Windows especificamente. Fontes: https://docs.astral.sh/uv/getting-started/installation/ ; https://docs.astral.sh/uv/guides/install-python/ ; https://github.com/astral-sh/uv (acesso 18/11/2026).

## 7. Defender e SmartScreen com executável PyInstaller sem assinatura

**SmartScreen ao dar dois cliques.** Documentação oficial: o SmartScreen confere arquivos baixados contra lista de programas maliciosos e contra lista de arquivos conhecidos e muito baixados; se o arquivo não está na lista, mostra aviso. Sem reputação (arquivo, URL, certificado), o item é tratado como de risco maior e gera aviso. A proteção é para arquivos da internet, e NÃO protege arquivos em locais internos ou compartilhamentos de rede UNC/SMB. Fonte: https://learn.microsoft.com/en-us/windows/security/operating-system-security/virus-and-threat-protection/microsoft-defender-smartscreen/ (acesso 18/11/2026).
O gatilho é a marca "Mark of the Web" (fluxo alternativo `Zone.Identifier`). NÃO achei página oficial do Learn sobre isso nesta busca; fontes secundárias (não oficiais): arquivo clonado com o cliente `git` não recebe `Zone.Identifier`; navegador adiciona a marca ao baixar; extrair um zip marcado com o Explorer propaga a marca, mas 7-Zip 24.09 por padrão não propaga; copiar para sistema de arquivos que não é NTFS perde a marca. Relato em https://www.outflank.nl/?p=1371 e https://isc.sans.edu/diary/31732 (acesso 18/11/2026; não oficiais). Resumo prático: `git clone` ou cópia pela pasta mapeada do Sandbox não marca; zip baixado pelo navegador marca e o `.exe` extraído dele em geral herda a marca.

**Falsos positivos do Defender com o bootloader do PyInstaller.** Fontes não oficiais ou parciais:
- Issue do PyInstaller #5579 (https://github.com/pyinstaller/pyinstaller/issues/5579): definir o checksum PE reduz detecções, mas "inconsistentemente" no Defender; o PyInstaller passou a definir o checksum.
- Tópicos relatam detecções como `Trojan:Win32/Wacatac.DC!ml` em onefile (https://python-forum.io/thread-32589.html), e a resposta de desenvolvedor do PyInstaller no Google Groups é reportar o falso positivo e, se possível, assinar o executável (https://groups.google.com/g/pyinstaller/c/wRz00GKw4cA). Relatos de que enviar à Microsoft resolveu: https://discuss.python.org/t/pyinstaller-false-positive/43171.
- Canal oficial da Microsoft para falso positivo: https://www.microsoft.com/wdsi/filesubmission/ (escolher o produto SmartScreen ou Defender; citado na página do SmartScreen).
- A página do wiki do PyInstaller "How to Report Antivirus False Positives" não pôde ser lida (retornou página de edição). Não confirmado em fonte primária.

**Ligar e desligar a proteção em tempo real dentro de uma VM de teste (somente documentação).**
- Interface: Segurança do Windows, Proteção contra vírus e ameaças, "Gerenciar configurações", chave "Proteção em tempo real" (a configuração é reativada sozinha pelo sistema depois de um tempo; o passo-a-passo da página de suporte da Microsoft não pôde ser aberto, 404, então isso não está confirmado em fonte primária).
- PowerShell elevado: `Set-MpPreference -DisableRealtimeMonitoring $true` desliga; `$false` (ou `0`) liga. O Learn mostra `Set-MpPreference -DisableRealtimeMonitoring 0` como forma de religar e manda rodar em "elevated PowerShell session". Parâmetro, alias `drtm`, tipo Boolean. Fontes: https://learn.microsoft.com/en-us/defender-endpoint/microsoft-defender-antivirus-using-powershell ; https://learn.microsoft.com/en-us/powershell/module/defender/set-mppreference (acesso 18/11/2026). O texto do `-DisableRealtimeMonitoring $true` para desligar não está em página oficial que li (só o religar); é o par lógico documentado pelo tipo Boolean.
- Verificação: `Get-MpComputerStatus | Select-Object IsTamperProtected, RealTimeProtectionEnabled` (`True` significa ligado). Fonte: https://learn.microsoft.com/en-us/defender-endpoint/tamper-protection-windows-configure
- Papel da Proteção contra Adulteração (Tamper Protection): quando ligada, a proteção em tempo real, o monitoramento de comportamento, a proteção na nuvem e outras configurações NÃO podem ser alteradas; mudanças feitas por ferramenta de gerência, Group Policy ou registro "podem parecer ter sucesso", mas são bloqueadas. Para mudar, desligar antes pela interface: Segurança do Windows, Proteção contra vírus e ameaças, Gerenciar configurações, chave "Proteção contra Adulteração" (requer administrador). Não se configura por PowerShell em uso normal; o comando temporário só funciona no modo de solução de problemas do Defender for Endpoint. Fontes: https://learn.microsoft.com/en-us/defender-endpoint/tamper-protection-overview ; https://learn.microsoft.com/en-us/defender-endpoint/tamper-protection-windows-configure (acesso 18/11/2026). Ordem prática: 1) desligar Proteção contra Adulteração, 2) desligar a proteção em tempo real, 3) religar na ordem inversa; ou, para o Defender ligado, não mexer.

## O que não consegui confirmar

1. Defender dentro do Windows Sandbox (se roda e se dá para desligar a proteção em tempo real lá): sem fonte oficial.
2. Convivência do Windows Sandbox com WSL2 e Hyper-V: sem frase oficial direta; só dedução pela arquitetura (mesmo hipervisor). Testar.
3. Tamanho do ISO do Windows 11 Enterprise (26H2) e do Windows 10 Enterprise 22H2; validade e URL do Windows 10 (a página oficial hoje redireciona; indícios fortes de descontinuação).
4. Se o Windows 10 limpo já traz `vcruntime140.dll` (provavelmente não) e se o executável PyInstaller onefile precisa do redist ou do UCRT em Windows 10 limpo.
5. MariaDB 11.8 zip: se precisa do VC++ Redistributable. Testar `mariadbd.exe --version` em Windows limpo. Também: o winget só tem MariaDB 12.x e 13.x (o diretório do manifesto lista 12.1, 12.2, 12.3 e 13.0), não 11.8.
6. Se o Chromium do Playwright roda no Windows 10 (a documentação atual lista só Windows 11 e Server 2019 em diante) e se `playwright install` dispensa administrador.
7. `Add-AppxPackage` e `Repair-WinGetPackageManager` sem administrador: sem afirmação explícita na documentação; testar.
8. Valor "KB10D" nos pré-requisitos do Sandbox novo (texto literal da página).
9. Opção `/SILENT` do instalador do Ollama (o manifesto é Inno, mas a página do Ollama não documenta).
10. Passo a passo oficial da interface do Defender para desligar a proteção em tempo real (a página de suporte da Microsoft deu 404) e texto oficial de `-DisableRealtimeMonitoring $true`.
11. Mark of the Web, `git clone` sem marca e extração de zip: só fonte secundária, nenhuma página oficial do Learn aberta.
12. Seção do manual do VirtualBox sobre Hyper-V/NEM e licença atual do VMware Workstation para uso comercial.
13. Wiki do PyInstaller sobre falsos positivos (página não carregou).
14. Existência dos arquivos 8.2 nos arquivos do PHP (listagem de https://downloads.php.net/~windows/releases/archives/ não aberta); só o manifesto do winget, que aponta para o zip `php-8.2.35-Win32-vs16-x64.zip`.
